# Proactive Messaging

In [Sending Messages](./), you were shown how to respond to an event when it happens. However, there are times when you want to send a message to the user without them sending a message first. This is called proactive messaging. You can do this by using the <LanguageInclude content={{"csharp": "`SendAsync`", "typescript": "`send`", "python": "`send`"}} /> method on your app instance. This approach is useful for sending notifications or reminders to the user.

The main thing to note is that you need to have the <LanguageInclude section="conversation-id-field" /> of the chat or channel that you want to send the message to. It's a good idea to store this value somewhere from an activity handler so that you can use it for proactive messaging later.

Then, when you want to send a proactive message, you can retrieve the <LanguageInclude section="conversation-id-field" /> from storage and use it to send the message.

In this example, you see how to get the <LanguageInclude section="conversation-id-field" /> using one of the activity handlers. This is a good place to store the conversation id, but you can also do this in other places like when the user installs the app or when they sign in. The important thing is that you have the conversation id stored somewhere so you can use it later.
:::

## Targeted Proactive Messages

Targeted messages, also known as ephemeral messages, are delivered to a specific user in a shared conversation. From a single user's perspective, they appear as regular inline messages in a conversation. Other participants won't see these messages.

When sending targeted messages proactively, you must explicitly specify the recipient account.

## Proactive Threading

Threads (reply chains) are rendered visibly in Teams channels and 1:1 bot chats. Where threads are not shown, messages appear flat, and passing a reply chain id has no visible effect.

To proactively send a message as a reply in a thread, use <LanguageInclude section="app-reply-method-name" /> with the id of the chat or channel and the id of the message that roots the reply chain.
Take both from `channelData` on the inbound activity.
Use `channelData.chat.id` in a 1:1 chat or `channelData.channel.id` in a channel, and `channelData.replyChain.id`, the id of the message at the root of the reply chain.

<LanguageInclude section="threading-proactive-example" />

To send a new top-level (non-threaded) message instead, send to the id of the chat or channel with <LanguageInclude section="app-send-method-name" />.

<LanguageInclude section="threading-top-level-example" />

A proactive call has no inbound activity to take an identity from. When the recipient is an agentic user, pass its identity from the inbound activity's recipient. Without it, the call uses the app's own credentials instead of the agentic user's. An agentic app cannot get an app-only token, so the call fails with an authentication error (`AADSTS82001`) and nothing is sent.
